# جسر التحول — صوت الموظف

منصة ويب للجوال يشغّلها **سفير التغيير** في منشأة صحية أثناء الانتقال إلى شركة الصحة القابضة.
يفتحها الموظف من جواله بلا حساب فيسأل أو يشارك مخاوفه أو تحديًا أو اقتراحًا أو شائعة سمعها،
وتصل المشاركة **مجهولة المصدر** إلى لوحة سفير التغيير مُصنَّفة ومجمّعة، فيحيلها إلى فريق التحول،
ثم تُنشر الإجابة الرسمية ويتابعها الموظف برمز.

---

## التشغيل محليًا

```bash
pnpm install
cp .env.example .env.local        # املأ القيم — ولا ترفع هذا الملف
pnpm db:migrate                   # مطبَّق مسبقًا على Supabase — يعمل بلا أثر
pnpm db:seed                      # مزروع مسبقًا — قابل لإعادة التشغيل بلا تكرار
pnpm dev                          # http://localhost:3000
```

بعد `db:seed` يفتح الموقع ممتلئًا: قضايا حيّة، جسر معرفة بثلاثة تبويبات، أسئلة وإجابات،
شائعات بمواقفها، رحلة التحول، وأربعة أسابيع من النبض. **لا شاشة فارغة عند أول فتح.**

لوحة سفير التغيير على `/admin`، والدخول برمز `ADMIN_PASSCODE`.

---

## المتغيرات

| المتغير | الغرض |
|---|---|
| `DATABASE_URL` | اتصال Supabase عبر الـ pooler (منفذ 6543) — تستخدمه دوال الخادم |
| `DIRECT_URL` | الاتصال المباشر (منفذ 5432) — للترحيلات والبذر فقط |
| `REF_CODE_PEPPER` | مِلح تلبيد رمز المتابعة ومعرّف الجهاز · `openssl rand -hex 32` |
| `ADMIN_PASSCODE` | رمز دخول لوحة السفير (بلا حساب مستخدم) |
| `CRON_SECRET` | ترويسة تحمي `/api/cron/retention` · `openssl rand -hex 32` |

القائمة نفسها تُضاف في Vercel للبيئات الثلاث، وفي أسرار GitHub Actions.

## الأوامر

```bash
pnpm dev · build · start
pnpm lint · typecheck · test · e2e      # كلها يجب أن تكون خضراء
pnpm verify                             # lint + typecheck + check:schema + test
pnpm check:schema                       # حارس الخصوصية: لا عمود يعرّف بشخص
pnpm budget                             # الحزمة الأولى < ١٨٠KB مضغوطة (بعد build)
pnpm db:push · db:migrate · db:generate · db:seed · db:studio
```

بيئات تُثبّت Chromium خارج مسار Playwright الافتراضي: اضبط `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.

## الخصوصية بالتصميم لا بالوعد

- **لا عمود لاسم ولا رقم وظيفي ولا بريد ولا جوال** في أي جدول. يفحص ذلك `pnpm check:schema`
  ويفشل البناء في CI إن ظهر أحدها.
- **لا تسجيل لعناوين IP** في أي طبقة، ولا تحليلات طرف ثالث في واجهة الموظف. يتحقق من ذلك
  اختبار Playwright يرصد كل طلب خارجي ويطالب بأن تكون القائمة فارغة.
- **تنقية مزدوجة:** على الجهاز في شاشة المراجعة، ثم على الخادم قبل التخزين. يُخزَّن المنقّى فقط،
  ولا يُكتب النص الأصلي في أي سجل — السجلات تحمل رسالة الخطأ وحدها.
- **رمز المتابعة** يُخزَّن `sha256(code + PEPPER)` فقط، ويُعرض للموظف مرة واحدة.
- **معرّف الجهاز** يُولَّد عشوائيًا في المتصفح، يُلبَّد قبل الإرسال، ثم يُلبَّد ثانية على الخادم،
  ويُجدَّد كل ٣٠ يومًا. يمنع التكرار ولا يعرّف بشخص.
- **عتبة الظهور ٧:** لا يُعرض تقسيم حسب القسم قبل وجود سبع مشاركات داخله.
- **لا نشر تلقائي:** كل إجابة وكل موقف من شائعة يمر باعتماد بشري، والمصدر إلزامي في المخطط نفسه.

اختبار `e2e/privacy.spec.ts` يرسل نصًا فيه اسم ورقم وظيفي وجوال وبريد وهوية، ثم يتحقق أن شيئًا
منها لا يظهر في شاشة المراجعة ولا في رد المتابعة ولا في وارد السفير ولا في تقرير الأسبوع.

## النشر

1. **Supabase** — جاهز: مشروع `Salwa's Project` (المرجع `woureabyrnjlgfxcbaea`، المنطقة
   `ap-northeast-2`) عليه المخطط كاملًا والبذر، وRLS مفعَّل على الجداول الخمسة عشر بلا سياسة
   واحدة أي رفض كامل لدورَي `anon` و`authenticated`. لا يُستخدم `supabase-js` في المتصفح،
   ولا يُنشر أي مفتاح Supabase في كود العميل. يبقى نسخ `DATABASE_URL` و`DIRECT_URL` من
   Project Settings ← Database إلى `.env.local` وإلى Vercel.
2. **Vercel:** اربط المستودع، وأضف المتغيرات الخمسة للبيئات الثلاث، واختر منطقة الدوال الأقرب
   لقاعدة البيانات، واستخدم Node runtime لا Edge. **عطّل Vercel Analytics و Speed Insights**
   على واجهة الموظف. `vercel.json` يجدول مهمة الاحتفاظ اليومية.
3. **GitHub:** فعّل حماية `main` (لا دفع مباشر، والدمج عبر PR بعد نجاح الفحوصات).
